# REPORT_FORMAT.md — Review report format and content rules

Every review creates a timestamped run directory under the test-output root:
```text
review-runs/<run-id>/
├── DIRECTORY_REVIEW.md
├── INVENTORY.csv
├── PROPOSED_ACTIONS.csv
├── UNKNOWNS.md
├── RUN_METADATA.json
└── VALIDATION_RESULTS.md
```

## DIRECTORY_REVIEW.md — required sections
1. Target and resolved target.
2. Run ID and timestamps.
3. Mode: `READ_ONLY_REVIEW`.
4. Scope boundaries.
5. Sources and registry versions loaded.
6. Counts by file type and classification.
7. Known protected assets.
8. Repository findings.
9. Reparse points and traversal blocks.
10. Sensitive-category counts without content excerpts (v1.0.2: sensitive-directory
    children are pruned and never appear; only blocked parent records + counts).
11. Placement recommendations.
12. Policy status for each recommendation.
13. Confidence and evidence.
14. Unknowns and conflicts.
15. Proposed future actions.
16. Strong statement: `NO ACTIONS PERFORMED`.

## INVENTORY.csv
One record per reviewed item where practical. Columns (v1.0.1/v1.0.2):
`path, item_type, size_bytes, extension, created, modified, attributes, is_reparse,
reparse_tag, reparse_status, blocked, block_reason, is_git_boundary, depth,
hash_sha256, sensitive, metadata_status`.
For very large directories support aggregate records and bounded sampling, but
document the threshold and do not silently omit content.

### Timestamps (v1.0.1, Correction B)
- Format: unambiguous **ISO 8601 with local offset** (e.g. `2026-08-30T11:48:21+10:00`).
- `created` = `CreationTime`, `modified` = `LastWriteTime`, read via filesystem metadata only.
- If a timestamp cannot be read, the field is left blank **and** `metadata_status`
  records `timestamp_unavailable:created` / `timestamp_unavailable:modified` — a
  value is never silently invented or left blank without a status.
- `attribute`/`reparse` access failures record `access_error:...` in `metadata_status`.

### Sensitive pruning (v1.0.2)
- A sensitive/protected directory is recorded as one `directory` row with
  `blocked=true`, `block_reason='sensitive boundary - not traversed'`, and its
  children are **not** present in INVENTORY at all.
- A sensitive **file** is recorded with metadata only; `hash_sha256` is blank.

### Path model (v1.0.1, Correction A)
- Each inventory `path` is the provider's display path.
- Run metadata records both `input_path` and `canonical_path` (the latter from the
  shared canonical path model), plus `path_style` (windows / wsl_native / wsl_unc / unknown)
  and runtime context.
- Shared model: `scripts/path_canonicalize.py`. It accepts Windows backslash /
  forward-slash, `\\wsl.localhost\...`, `\\wsl$\...`, and WSL-native `/...` forms,
  normalises separators, resolves `.`/`..` lexically, treats drive letters
  case-insensitively, prevents sibling-prefix confusion, rejects malformed
  drive-relative, empty, and relative paths, and fails closed when equivalence
  cannot be proven. It never traverses reparse points.

## PROPOSED_ACTIONS.csv (advisory only in v1)
`action_id, proposed_action, source_path, proposed_destination,
destination_policy_status, classification, reason, confidence, reversible,
blocked, block_reason, required_approval, source_evidence`.
**Every row must have `blocked=true` in v1** because execution is not implemented.
No action may be proposed for content inside a sensitive boundary (it is pruned and
never enumerated).

## RUN_METADATA.json
`run_id, mode, target, input_path, canonical_path, path_style, runtime_context,
generated_at, registries, counts (by_type, by_classification, by_extension),
reparse_point_count, git_boundary_count, sensitive_count, items_inventoried,
proposed_actions_all_blocked, fixture, no_actions_performed`.

## UNKNOWNS.md
Separate:
- missing evidence;
- stale evidence;
- conflicting evidence;
- unclassifiable items;
- decisions required from Michael;
- recommended next investigation.

## VALIDATION_RESULTS.md
Generated by `validate_review_output.py`, recording each check (PASS/FAIL):
- all required outputs present (VALIDATION_RESULTS.md self-generated);
- INVENTORY columns and path-safety (no path outside the explicit target);
- reparse handling (all reparse items blocked, none traversed);
- **target-root not a reparse point (v1.0.2)**;
- **sensitive-directory pruning (no sensitive children leaked; sensitive files not
  hashed) (v1.0.2)**;
- PROPOSED_ACTIONS structure and all-blocked;
- secret-safety (no secret patterns; category+count only, never values).

## Content rules
- **Never output matching content from sensitive files.** Report category/count only.
- **Never output or enumerate children of a sensitive/protected directory.**
- **Never print secret values** — password, API key, token, private key, recovery
  code, credential-bearing URL, household identifier, `.env` content.
- **Sanitize remote URLs**: strip userinfo (`user:pass@`) → `<redacted>@`.
- **Separate fact, policy, inference, confidence, and approval requirement** in every
  recommendation.
- Strong statement `NO ACTIONS PERFORMED` always present.
