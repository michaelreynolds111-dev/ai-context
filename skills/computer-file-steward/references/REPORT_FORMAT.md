# REPORT_FORMAT.md — Review report format and content rules

Every review creates a timestamped run directory under the test-output root:
```text
review-runs/<run-id>/
├── DIRECTORY_REVIEW.md
├── INVENTORY.csv
├── PROPOSED_ACTIONS.csv
├── UNKNOWNS.md
├── RUN_METADATA.json
└── VALIDATION_RESULTS.md
```

## DIRECTORY_REVIEW.md — required sections
1. Target and resolved target.
2. Run ID and timestamps.
3. Mode: `READ_ONLY_REVIEW`.
4. Scope boundaries.
5. Sources and registry versions loaded.
6. Counts by file type and classification.
7. Known protected assets.
8. Repository findings.
9. Reparse points and traversal blocks.
10. Sensitive-category counts without content excerpts.
11. Placement recommendations.
12. Policy status for each recommendation.
13. Confidence and evidence.
14. Unknowns and conflicts.
15. Proposed future actions.
16. Strong statement: `NO ACTIONS PERFORMED`.

## INVENTORY.csv
One record per reviewed item where practical. Minimal columns:
`path, item_type, size_bytes, extension, created, modified, attributes, is_reparse,
reparse_tag, blocked, block_reason, is_git_boundary, depth, hash_sha256, sensitive`.
For very large directories support aggregate records and bounded sampling, but
document the threshold and do not silently omit content.

## PROPOSED_ACTIONS.csv (advisory only in v1)
`action_id, proposed_action, source_path, proposed_destination,
destination_policy_status, classification, reason, confidence, reversible,
blocked, block_reason, required_approval, source_evidence`.
**Every row must have `blocked=true` in v1** because execution is not implemented.

## RUN_METADATA.json
`run_id, mode, target, generated_at, registries, counts (by_type, by_classification,
by_extension), reparse_point_count, git_boundary_count, sensitive_count,
items_inventoried, proposed_actions_all_blocked, fixture, no_actions_performed`.

## UNKNOWNS.md
Separate:
- missing evidence;
- stale evidence;
- conflicting evidence;
- unclassifiable items;
- decisions required from Michael;
- recommended next investigation.

## VALIDATION_RESULTS.md
Generated by `validate_review_output.py`, recording each check (PASS/FAIL):
- all six outputs present (VALIDATION_RESULTS.md self-generated);
- INVENTORY columns and path-safety (no path outside the explicit target);
- reparse handling (all reparse items blocked, none traversed);
- PROPOSED_ACTIONS structure and all-blocked;
- secret-safety (no secret patterns; category+count only, never values).

## Content rules
- **Never output matching content from sensitive files.** Report category/count only.
- **Never print secret values** — password, API key, token, private key, recovery
  code, credential-bearing URL, household identifier, `.env` content.
- **Sanitize remote URLs**: strip userinfo (`user:pass@`) → `<redacted>@`.
- **Separate fact, policy, inference, confidence, and approval requirement** in every
  recommendation.
- Strong statement `NO ACTIONS PERFORMED` always present.
